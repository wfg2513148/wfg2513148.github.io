Oracle APEX 26.2 全新发布

Oracle APEX 26.2 正式发布：开发更敏捷，AI 更实用，数据更安全

企业应用正在迎来新的期待：开发者希望更快响应变化，业务人员希望更轻松地使用数据，管理者希望在引入 AI 的同时，保持对权限和运行方式的掌控。

Oracle APEX 26.2，为这些需求带来了新进展。

2026 年 10 月 6 日，Oracle 正式宣布 Oracle APEX AI Application Generator 26.2 面向本地部署全面可用。Oracle Autonomous AI Database、OCI 及多云环境的推出将随后进行，具体时间以官方安排为准。[1]

**先解释一下这个新名称。**Oracle APEX 是运行在 Oracle Database 上的企业应用开发平台，支持通过可视化方式构建报表、表单和业务流程。官方此次使用的 Oracle APEX AI Application Generator 26.2，与本文简称的 Oracle APEX 26.2，指向同一 APEX 平台及其 26.2 版本；“AI Application Generator”强调它以 AI 辅助生成应用的产品定位，并不是另一个需要单独安装的“AI 插件”。[1][7]

开发者仍可使用 App Builder，也可以让 AI 编码助手结合 APEXlang 生成、修改应用定义，再由 APEX 平台执行。名称突出了 AI，APEX 原有的可视化开发与应用运行能力仍是基础。[8]

这次升级值得关注的，是三个方向：让开发迭代更精细，让 AI 融入日常操作，让数据访问更可控。

图 1｜Oracle 官方界面组合图：应用构建、交互报表与助手体验。来源：Oracle APEX 26.2 新特性官网。[2]

01 改一个页面，可以只导入这个页面

开发者经常遇到这样的情况：只调整了一个页面，却需要重新导入整个应用。

在 26.1 引入 APEXlang 之后，26.2 新增文件级导入：开发者可通过 SQL Developer for VS Code 的 Import File 按钮，或 SQLcl 的 -files 参数，将指定页面、受支持的共享组件文件导入已有应用。[3]

这让“修改—导入—验证”的循环更聚焦，也让 App Builder 与本地编辑器并行工作的团队更容易协作。导入前结合差异比较和拉取变更，可以减少覆盖他人修改的风险。

图 2｜APEXlang 的 Remote ↔ Local 差异比较：同一页面文件的变化并排展示，便于导入前检查。来源：APEX 26.2 Developer’s Companion。[14]

对正在采用源码管理和 AI 辅助开发的团队而言，这意味着日常小步迭代有了更合适的更新粒度。

**使用边界也很明确：**文件级导入主要服务于开发和测试；生产发布仍应遵循组织既有的完整应用部署流程。[3]

02 报表多一列指标，试着用一句话完成

业务分析中，临时增加一个计算指标，是再常见不过的需求。

APEX 26.2 的 AI 交互报表支持用自然语言创建计算列。例如，在官方演示中，用户描述“用金额乘以概率再除以 100，创建加权商机金额”，APEX 将其转换为标准交互报表计算。[4]

加权商机金额 = 金额 × 概率 ÷ 100

新增计算可以查看、修改、保存或移除，无需改变底层 SQL 查询和数据源。

图 3｜官网中的 CRM 商机报表截图。输入栏展示了创建 Weighted Pipeline 计算列的自然语言请求，图中尚未展示新列结果。来源：Oracle 新特性官网。[2]

图 4｜标准交互报表中的计算列结果示例：右侧 Available Budget（可用预算）列。它是独立的官方示例，并非上图 AI 请求的执行结果。来源：APEX 26.2 End User’s Guide。[15]

与此同时，报表界面也迎来更新，包括列头多选筛选、数字范围与日期筛选、拖拽调整列顺序等，让日常分析更顺手。[4]

图 5｜官方 26.2 用户指南中的列头菜单示意，展示排序与筛选入口；本图未展示新增多选筛选状态。来源：APEX 26.2 End User’s Guide。[16]

还有一个实用变化：**符合预设关键短语模板的常见操作，可直接处理，无需 AI 解释。**对于启用 AI 的报表，更复杂或存在歧义的请求仍进入 AI 处理流程。[4]

03 AI 智能体，开始有了更细致的“调节旋钮”

面对简单查询和复杂分析，应用需要的 AI 处理方式往往不同。

APEX 26.2 扩展了生成式 AI 服务的接口选择，包括 OpenAI Responses、Google Gemini Interactions，以及受支持的 OCI Generative AI 模型接口；相应端点与请求、响应格式由 APEX 处理。[5]

新增的 Reasoning Effort（推理强度），让开发者可以按智能体或具体请求调整模型的推理投入。较低强度可能减少响应时间和 Token 消耗，复杂任务则可按需选择较高强度；可用选项取决于服务商、接口和模型的支持情况。[5]

智能体还可以引导用户前往相关应用页面：开发者定义允许访问的目标和参数，最终 APEX URL 与校验信息由可信应用代码构建。[1]

这为企业提供了更实际的 AI 应用方式：既关注回答能力，也关注响应速度、使用成本和用户接下来的操作。

04 AI 走近业务数据，权限也要跟得上

当数据同时通过报表、表单和 AI 智能体被访问，企业需要一致的权限规则。

APEX 26.2 新增对 Oracle Deep Data Security 的集成，将已验证的用户和应用身份传递给数据库，由数据库按安全上下文执行细粒度的数据授权，覆盖行、列及具体值级别。[1][2]

在支持的 AI Agent 工具中，SQL 以请求用户的安全上下文执行。向智能体多问一句，并不会因此获得更多数据权限。[1]

APEX 应用授权与数据库数据授权各有职责：前者管理用户能在应用中访问什么、执行什么操作；后者约束 SQL 能读取或修改哪些数据。该能力需要相应 Oracle AI Database 功能与配置支持。

05 连接 OCI 服务，凭据管理更省心

应用读取 OCI 对象存储、调用生成式 AI 服务时，也需要管理连接身份。

26.2 支持在 OCI Native Authentication 中，通过 APEX Web Credential 引用 DBMS_CLOUD 数据库凭据，使用 Resource Principal 或 Database Tools Identity。[6]

这样，应用可以在满足相关配置条件后访问 OCI 服务，无需在 APEX Web Credential 中保存某个用户的 API 私钥。资源访问权限继续由 OCI IAM 策略决定，托管身份负责相应凭据的管理与轮换。

对于需要持续集成云服务的应用，这减少了围绕个人密钥开展维护的工作。

06 日常开发与运行体验，也在持续打磨

除了 AI 和开发流程，26.2 还带来了工作流与界面方面的实用更新。[2]

  • **工作流更灵活：**支持草稿活动、自定义任务结果，以及运行中工作流实例向新模型版本迁移。
  • **流程更易沟通：**工作流图可导出为 PNG 或 SVG，用于文档和评审。
  • **界面更精细：**Universal Theme 增强 Iris 外观、导航辨识度与样式控制。
  • **运维更清晰：**邮件队列报告提供更丰富的投递与失败情况信息。

图 6｜员工评估工作流的运行图，显示流程连接与节点状态，用于理解工作流界面。来源：APEX 26.2 End User’s Guide。[17]

图 7｜Oracle 官方 App Builder 与页面设计器组合截图，用于展示开发环境。来源：Oracle APEX 26.2 新特性官网。[2]

07 准备升级？先把平台、工具与 Skills 一起对齐

APEX 26.2 的升级，涉及数据库中的 APEX 引擎、Web 访问服务、开发工具以及 AI 辅助开发资料。对自主管理的环境，建议按下面几项逐一检查。

第一步：核对最低版本，别沿用 26.1 的清单

根据 APEX 26.2 安装指南，本次版本要求如下。[9]

组件官方要求或功能条件
Oracle Database 19cRU 19.18（2023 年 1 月）或更新版本
Oracle AI Database 26ai数据库版本 23.26.0（2025 年 10 月）或更新版本
ORDS26.3.0 或更高版本
SQLcl26.3.0 或更高版本
SQL Developer for VS Code比较并拉取 APEXlang 变更需 26.3 或更高版本；文件级导入还要求目标 APEX 与导出应用均为 26.2 或更高版本。[3]

**注意版本号并不一一对应：APEX 升级到 26.2，配套的 ORDS、SQLcl 要达到 26.3.0。**同时应按所选工具版本核对 Java 环境，不能只替换 APEX 安装包。

第二步：同步静态资源，先完成升级演练

建议先备份数据库、应用导出文件和 ORDS 配置，在测试环境完成升级与关键业务回归，再安排生产切换。

APEX 的 JavaScript、CSS 等静态资源也要与数据库中的版本匹配：使用本地资源时同步更新 images 目录及其服务映射；使用 Oracle CDN 时核对对应补丁版本。官方当前列出的 26.2.0 CDN 地址为：[10]

https://static.oracle.com/cdn/apex/26.2.0/

升级后重点验证登录、报表、表单、文件上传、REST 接口和自定义插件。已有生成式 AI 服务还应检查 Provider API、自定义请求头及附加参数是否适配新接口。[5]

第三步：把 GitHub Oracle Skills 更新纳入升级计划

**使用 Codex、Claude 等工具开展 APEXlang 开发的团队，还要同步关注 GitHub 官方仓库 oracle/skills。**其中 apex/apexlang 提供 APEXlang 开发指导、模板、工作流和校验工具；db 目录提供数据库与 SQLcl 等配套指导。[11]

这些 Skills 为 AI 助手提供开发依据，需要独立安装和更新。升级数据库中的 APEX，并不会自动刷新开发电脑或团队环境中的 Skills。

Oracle 官网给出的同步方式是：[8]

SQLcl 26.3 还增加了用于安装、更新 AI Skills 的 skills_sync MCP 工具，以及面向 APEXlang 文件的 CodeScan 规则。[12]

建议团队将 APEX 版本、SQLcl 版本、Skills 来源与更新记录 一并纳入项目维护，并在更新后确认 AI 工具实际加载了新内容，再用一个小应用完成生成、校验与导入验证。

图 8｜VS Code 中的 APEXlang 校验示例：编辑器指出无效的模板选项，并给出可用值。图中绿色标注来自 Oracle 原图。来源：APEX 26.2 Developer’s Companion。[14]

**版本判断要以 26.2 文档为准。**本次核对的官方 Skills README 仍包含 26.1 的基线说明，不能将其中 SQLcl 26.1.2 的要求直接套用于 APEX 26.2；Skills 的具体适配状态应结合仓库最新内容检查。[9][11]

第四步：检查已知问题，再使用文件级导入

截至 2026 年 10 月 7 日，官方已知问题页列出 Bug 40091133：单独部署 application.apx 可能意外改变应用别名，并移除应用当前主题；官方给出的恢复方式是执行完整 APEXlang 导入。[13]

因此，试用单文件导入前应先查看最新 Known Issues 与补丁说明。尤其要区分“导入一个页面文件”与“导入应用级定义文件”；生产发布仍按完整应用的验证、部署和恢复流程执行。[3]

把配套版本、静态资源、Skills 和已知问题一起检查到位，才能把 26.2 的新能力稳妥用进日常开发。
